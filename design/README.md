### Figma에는 있지만 코드에는 아직 없는 것

2026-11-12에 사용자가 작업 중인 Figma(https://www.figma.com/design/ZbeBrS0o5012SNFrGZNyIU, 페이지 `SS 01 ·
키오스크 새 흐름`, `SS 02 · 네컷 프레임 · 휴대폰 · 미디어월`)의 흐름을 반영했다(D77, D78): O 속 별,
2×2 틀, 한국어/English, 이전. 아래는 **일부러 만들지 않았다.**

- **이름 입력 화면.** 사용자 결정(2026-11-12): 만들지 않는다. 코드는 이름을 받지 않는다(개인 정보 규칙).
  2026-11-13 Figma 편집용 네컷 프레임에서도 이름 입력 버전과 이름 길이 검증 시안을 제거해,
  성구 있음/없음 두 버전만 남겼다. 운영 코드에는 방문객 이름 입력·합성·저장 기능이 없다.
- **두 장의 선택 카드 동의 화면.** 코드는 "네, 띄워주세요 / 아니요, 저만 볼게요" 두 버튼을 같은 크기로
  보여 준다(같은 원칙). 문구는 사용자 문구 그대로 둔다(D76).
- **틀 고르기·사진 확인 화면의 구성 (D88, 2026-11-14).** Figma KIOSK 페이지와 다르다. 틀 고르기는
  스크롤 목록 대신 "큰 미리보기 하나 + 모든 틀의 작은 타일"이고, 가로 화면의 사진 확인은 6장 한 줄이
  아니라 3 × 2 옆에 제목·버튼이다. 태블릿에서 화면이 넘치던 것을 고치면서 바꿨다. Figma KIOSK
  페이지의 틀 고르기 구역(2·5)에는 2026-11-17 키오스크 화면 캡처(820 × 1180, 틀 16종)를 옆에
  붙였고, SS 02 `🔄 코드 현재 틀 16종` 구역에 `docs/screenshots/frame-*.jpg` 16장을 올렸다. 편집용
  시안 자체는 아직 옛 구성이다.
- **격자(grid) 미디어월.** 만들지 않았다. 코드의 미디어월은 줄에 사진을 거는 방식 그대로이고,
  배경만 SS 03의 STUDIO SHALOM 장면 8종으로 바뀌었다(D85, 아래 "미디어월 테마").
- **Figma 문구 변경**(예: "6장 모두 다시 찍기", 키오스크 상단 막대의 "처음으로" 위치). 손님 문구는 사용자가
  정한 것만 바꾼다(D76). "처음으로"는 코드에서 화면 아래에 그대로 있다.

### 프레임 옮기는 법

프레임은 코드에서 데이터다(`lib/compositor/types.ts` 의 `FrameDefinition`). Figma 컴포넌트의 레이어가
그 필드와 1:1로 대응한다.

| Figma 레이어                         | `FrameDefinition` 필드                                                            |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| 컴포넌트 크기 (600×1800)             | `outputWidth`, `outputHeight`. 저장할 때 2배(`KIOSK_CONFIG.outputScale`)          |
| 컴포넌트 채우기                      | `background` (단색 또는 위→아래 그라데이션)                                       |
| `Photo/Slot` 4개                     | `slots[i]`: x, y, width, height(4:3), 기울기 `rotation`                           |
| 사각형 (액자·창틀·줄·폴라로이드)     | `decorations` 의 `rect`: 색 또는 그라데이션, 모서리, 기울기, 그림자               |
| 영문 로고·제목, 반짝이, 테이프, 빛길 | `decorations` 의 `image`: Figma에서 내보낸 파일(`public/frames/`, SVG·PNG)과 위치 |
| 한글 문구                            | `decorations` 의 `text` (Noto Sans KR)                                            |
| 레이어 순서                          | `decorations` 순서. 사진은 `{ type: "photo", slot }` 이 있는 자리에 그린다        |

SVG로 옮기는 법: Figma MCP `download_assets` 로 해당 노드를 SVG로 내보낸 뒤, 내보내기가 덧붙인
회색 바탕(`#F5F5F5`)과 틀 전체 크기의 바탕 사각형을 지운다. `clipPath` 안의 사각형은 지우지 않는다.
비어 있는 `clipPath` 는 그림 전체를 가린다. `tests/unit/frames.test.ts` 가 두 가지 모두 검사한다.
위치는 내보낸 파일의 `translate(-x -y)` 값이다.

주의할 점:

- **사진 칸은 4:3** 이어야 한다(`KIOSK_CONFIG.captureAspect`). 미리보기와 결과가 같은 비율이어야 해서,
  다르면 `tests/unit/frames.test.ts` 가 실패한다.
- **글자 위치:** 코드는 글자의 기준선(baseline)에 y를 둔다. Figma 텍스트 상자의 위쪽 y에
  `글자 크기 × 0.88` 을 더한 값이 코드의 y다. 가운데 정렬 글자의 x는 프레임 폭의 절반이다.
- **날짜:** `{date}` 는 촬영일(한국 시간, `2026.12.24` 꼴)로 바뀐다. 지금 틀 A~D는 쓰지 않는다.

### 로고 규칙 (코드가 검사함)

`tests/unit/frames.test.ts` 가 모든 프레임에 대해 확인한다. 하나라도 어기면 `npm run check` 가 실패한다.

- 프레임마다 `brand` 표시가 된 락업 그림이 하나 있다.
- 출력 폭의 38% 이상, 높이 80px 이상(600×1800 기준). 예전 한 줄 워드마크는 폭 55%였다. 네 줄로 쌓은
  락업은 같은 글자 높이에 폭이 덜 필요하다(높이 80px이면 SHALOM 대문자가 약 32px, 예전 글자는 약 30px).
- SVG의 비율(422×156.13) 그대로, 틀의 가운데에 그린다(`config/frames/shared.ts` 의 `lockupBox`).
- 글자는 윤곽선(path)이다. `<text>` 나 글꼴 이름이 있으면 실패한다(캔버스에는 웹 글꼴이 없다).
- 사진 칸보다 아래에 있다(얼굴을 가리지 않게).
- 바탕색과 대비 4.5:1 이상.

### 락업 SVG 만드는 법

`public/frames/{navy,wood,cream}-lockup.svg` 는 Figma에서 내보낸 것이 아니라, 함께 배포하는 글꼴 파일

STUDIO 30(자간 0.4em), 구분선 44×1.6, 평화의 벽 24(자간 0.3em), 줄 사이 13·17·17 이다. 색은 틀마다 예전

바꿔 그렸다. 나머지 그림은 그대로다.

### 코드로 그리는 틀 (2026 컬렉션, D102)

빈티지·땅에는 평화·아날로그·제주의 겨울 네 틀은 Figma에서 내보내지 않고 `scripts/frame-collection.mjs` 가
그린다. 같은 입력이면 같은 파일이 나온다(종이 얼룩·필름 입자는 시드가 고정된 난수).

- **배치:** `config/frames/collection-layout.ts` 하나를 틀 정의와 스크립트가 함께 읽는다. 600×1800,
  사진 468×351(4:3) 네 장, 사진 사이 18px, 위 120px는 제목, 마지막 사진 아래는 로고와 한 줄 글.
- **그리는 순서:** 그림(`<id>-art.svg`, 종이·테두리·제목·장식) → 사진 4장 → 로고(`<id>-lockup.svg`).
  사진 위에 올라가는 것은 빈티지 틀의 앨범 모서리(`vintage-christmas-corners.svg`, 사진 모서리 22px)뿐이다.
- **색:** 틀마다 `COLLECTION_PALETTES` 의 `paper`·`ink`·`accent`. 로고는 `shalom-lockup.svg` 의 색만 바꿔
  만든다(글자와 O 안의 별은 `ink`, 구분선은 `accent`).
- **글자:** Cormorant Garamond(제목, 숫자는 라이닝 숫자)와 IBM Plex Mono(필름 표시)를 opentype.js로 윤곽선으로
  바꾼다. 웹 글꼴이 늦게 와도 저장되는 사진은 같다.
- **고치는 법:** 스크립트나 배치 파일을 고친 뒤 `node scripts/frame-collection.mjs` 를 돌린 다음 바뀐 SVG를 함께
  커밋한다. `tests/unit/frame-collection.test.ts` 가 공통 배치, 그리는 순서, 사진 위 장식, SVG 내용(글꼴·외부
  참조 없음, 크기)을 검사한다.

- 768×1024에서 Figma와 같은 픽셀, 다른 크기는 `--fx`(= min(폭/768, 높이/1024))로 비율 유지.
- 본문(제목·카드·미리보기·옵션 줄)은 바인더 링 오른쪽(`--ring-safe`: 768×1024에서 100px)부터.
  머리말(로고·점)과 하단 바(처음으로·이전·주요 버튼)는 Figma처럼 링 위아래, x 30에서 시작한다.
- 하단 바 고정: 「처음으로」(30→204) + 「이전」(224→333, 되돌아갈 곳이 있을 때) + 주요 버튼(353→732, 「이전」이
  없으면 224부터; 높이 76, 글자 28, 화면 아래 24px), 내용과 32px.
- 「이전」 자리(2026-11-25, 사용자 결정): 머리말에서 내려 하단 바 「처음으로」 옆으로. Figma는 `Kiosk/Header` 의
  「이전 버튼」 속성을 끄고 `Kiosk/Footer (코드)` 에 새 변형 `Type=HomeBack`(`983:184`)을 쓴다. 머리말 높이(75)는
  그대로라 그 아래는 움직이지 않았다.
- 「다시 찍기」(2026-11-25, 사용자 결정): 사진 확인 화면(`395:1387`)에 보조 버튼, 확인 창은 `985:1759`
  (섹션 `386:426`). 한 사람에 한 번, 같은 틀로 여섯 장 전부. 문구는 Claude가 썼다(사용자 확인 전, D76).
- 터치 크기는 어느 크기에서도 48px 아래로 내려가지 않는다.
- 머리말·하단(2026-11-23, 모든 부스 화면 공통): 「이전」·「처음으로」 높이 75, 글자 26 Medium, 선 2px. 워드마크 30px.
  진행 점 지름 16, 간격 14. 틀 고르기·옵션 화면의 주요 버튼은 Figma처럼 평면(입체감·그림자 없음)이다.
- 3:4 화면(768×1024)의 틀 고르기·옵션 화면은 바인더 배경을 Figma처럼 제 크기(820 폭)로 왼쪽 위에 맞춘다.
- 띄어쓰기 폭: Figma의 Noto Sans KR 공백은 0.224em인데 같은 폰트 파일이 Chromium에서는 0.28em, WebKit에서는 0.227em으로
  그려진다. 부스가 시작할 때 공백을 재서(`lib/kiosk/space.ts`) 차이만큼만 `word-spacing` 으로 뺀다.
- 화면 4개의 위치·크기·픽셀 비교: `e2e/figma-parity-screens.spec.ts`, 결과 `docs/FIGMA_PARITY.md`.

## 새 프레임을 추가하려면

1. Figma `STUDIO SHALOM · Frame, Phone & Wall` 에서 기존 틀을 복제해 고친다. 2026 컬렉션처럼 코드로 그리는
   틀은 `scripts/frame-collection.mjs` 에 그리는 함수를 하나 더하고 `COLLECTION_PALETTES` 에 색을 넣는다.
2. `config/frames/` 에 새 파일을 만들고 위 표대로 값을 옮긴다. 부스의 틀이면 `config/frames/v2.ts` 의
   `FRAME_CARDS` 에 카드나 변형으로 넣는다(`V2_FRAMES`). 휴대폰 페이지의 틀은 `config/frames/index.ts` 의 `FRAMES` 다.
3. `npm run check` (프레임 규칙과 로고 규칙), `npm run test:e2e` 를 돌린다.
4. 부스에서 `/kiosk?camera=mock` 으로 촬영해 결과를 눈으로 확인한다.
