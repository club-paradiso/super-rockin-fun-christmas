### 시험 중 고친 것

- `e2e/browser-camera.spec.ts` "처음으로" 버튼이 두 개(화면 + 하단) → 자기 버튼이 있는 화면에서는 하단
  "처음으로"를 숨김. 2.0에서 생긴 회귀였고 E2E가 잡았다.
- `e2e/admin.spec.ts` (Supabase 전용): PR #27이 등록 오류 문구를 바꾸고 이 시험을 안 고쳤다. CI 러너가
  돌지 않아 그동안 드러나지 않았다. 현재 문구로 고침.
- Supabase 통합 시험 2곳: 설정 함수 서명(새 인자)과 하트비트 응답(새 필드)에 맞춤.

### 환경 메모 (코드와 무관)

- 저장소의 Playwright 1.56.1이 찾는 브라우저 빌드가 컨테이너에 없어서, 컨테이너에 설치된 Chromium을
  그 경로로 연결해 실행했다(저장소 밖). CI는 `npx playwright install`로 자기 브라우저를 받는다.
- Docker 데몬을 직접 띄워 `supabase start`(CLI 2.120.0, CI와 같은 버전)로 로컬 스택을 만들었다.
  새 마이그레이션 `20261108090000_v2_kiosk_mode.sql`이 기존 3개 위에 적용됐다.

## 4. 측정 (휴대폰 사진 서버 처리, 이 컨테이너)

합성 이미지, 서버 처리(`lib/mobile/image.ts`와 같은 단계) 5회 중앙값:

| 입력                                  | 입력 크기 | 결과               | 중앙값  | 최대    |
| ------------------------------------- | --------- | ------------------ | ------- | ------- |
| 12MP 노이즈 JPEG (최악)               | 7.65 MB   | 2048×1536, 0.79 MB | 759 ms  | 802 ms  |
| 12MP 단색 JPEG                        | 0.07 MB   | 2048×1536, 0.01 MB | 148 ms  | 152 ms  |
| 2048px 노이즈 JPEG (휴대폰이 줄인 뒤) | 1.97 MB   | 2048×1536, 1.30 MB | 1039 ms | 1054 ms |

- 휴대폰이 먼저 2048px로 줄이므로 최악의 경우에도 요청은 약 2 MB로 서버 한도 4 MB, Vercel 4.5 MB 아래.
  12MP 원본을 그대로 보내면(7.65 MB) 한도를 넘는다 — 휴대폰 쪽 축소가 필요한 이유.
- 노이즈는 압축이 가장 안 되는 극단값이다. 실제 사진 크기·처리 시간은 실기기에서 재야 한다(미검증).
- 성능 최적화 전후 비교는 없다: 이번 작업은 기존 경로의 성능을 바꾸지 않았다.
