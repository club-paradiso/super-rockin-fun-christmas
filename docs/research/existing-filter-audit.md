# 기존 필터·색 보정 감사 (2026-11-23)

리포에서 사진의 색을 건드리는 코드를 전부 찾아 읽고, 수치로 잰 결과다. 추측한 구조는 없다. 수치는
기존 톤 함수(`applyTone`)에 기준 색을 넣어 나온 값이고, 색상·채도는 OKLCh로 쟀다. 비교 기준인
시장조사는 `docs/research/color-market-research.md`.

## 1. 색을 건드리는 곳 전부

| 위치                                                         | 하는 일                                                                                      | 손님 사진의 색을 바꾸나                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `lib/compositor/tone.ts`                                     | 톤 4종(흑백 `mono`, 세피아 `sepia`, 플래시 `flash`, 컬러 `film`). Figma 내보내기에서 잰 곡선 | **바꾼다. 유일한 색 처리다**              |
| `lib/compositor/compose.ts` `tonedPhoto`                     | 사진을 칸 크기로 줄인 뒤 `getImageData`로 톤을 입혀 틀에 그린다                              | 톤을 적용하는 자리                        |
| `config/frames/v2.ts` `photoTone`                            | 틀 15종 중 8종이 톤을 가진다(필름 3컷 4종, 폴라로이드 3컷, 35mm 필름 4컷 3종)                | 어떤 틀이 어떤 톤인지                     |
| `lib/camera/capture.ts` `grabFrame`                          | 자르기와 좌우 반전                                                                           | 안 바꾼다                                 |
| 촬영 화면 `<video>`, 확인·고르기 화면 `<img src={shot.url}>` | 카메라 영상과 찍은 컷을 그대로 보여 준다                                                     | 안 바꾼다(4절의 문제)                     |
| `app/globals.css` `.print-develop`                           | 완성본이 2.8초 동안 인화되듯 떠오르는 연출(CSS `filter`, 끝나면 `none`)                      | 안 바꾼다. 화면 연출이고 저장 파일과 무관 |
| `app/globals.css` `.wall-ambient` 등                         | 미디어월 여백의 흐린 배경, 봉투 그림자                                                       | 안 바꾼다. 사진이 아니다                  |
| `config/kiosk.ts` `outputQuality: 0.92`                      | 최종 JPEG 인코딩                                                                             | 브라우저 기본 크로마 서브샘플링만 거친다  |
| `lib/mobile/image.ts`, `lib/moderation/image.ts`             | 휴대폰 사진 재인코딩, AI 검토용 사본                                                         | 방향만 바로잡고 메타데이터를 지운다       |

틀 15종 중 7종(필름 4컷 2종, 폴라로이드 1컷, 성경 구절 4컷, 체크 2컷 2종, 레이스 1컷)과 휴대폰
참여용 예전 틀 20종은 **색 처리가 전혀 없다.** 카메라가 준 그대로 나간다.

## 2. 톤 4종 진단

| 톤             | 검정 → 흰색                                        | 피부                                                                                                                      | 빨강·초록                                   | 진단                                                                                                                                                                                           |
| -------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 흑백 `mono`    | 0 → 255. 128은 129. 곡선이 사실상 직선             | 가장 밝은 피부 230, 밝은 피부 206                                                                                         | 장식 빨강 101, 솔잎 초록 77                 | 선형광 휘도로 탈색만 한다. 하이라이트를 누르지 않아 카메라가 날린 곳은 그대로 255다. 밋밋하지만 틀리지는 않았다                                                                                |
| 세피아 `sepia` | **(46, 31, 20) → (244, 230, 204)**                 | 흑백이라 해당 없음                                                                                                        | 장식 빨강 (137, 99, 68), 솔잎 (112, 74, 44) | 검정이 46까지 떠 있고 입력 0~약 24가 전부 같은 값이다: **뿌옇고 섀도 디테일이 없다.** 입력 225부터 위는 전부 (244, 2xx, 20x)로 같다: **하이라이트가 평평하게 잘린다.** 양 끝 약 10%씩을 버린다 |
| 플래시 `flash` | (2, 3, 0) → (255, 255, 252). 128은 143             | 색상이 최대 8.3° 돌아 75°까지 간다(피부 띠는 40~70°). 어두운 피부의 채도가 1.13~1.18배. 가장 밝은 피부는 R이 255에 붙는다 | 장식 빨강 채도 1.07배, 솔잎 초록 1.10배     | 채널별 곡선이라 밝히는 만큼 채도가 따라 오른다. **어두운 피부는 주황으로, 밝은 피부는 하얗게 날아가고, 크리스마스 빨강·초록은 더 튄다.** 시장조사 8절 1번 그대로다                             |
| 컬러 `film`    | (4, 0, 0) → (255, 255, 252). 128은 (129, 128, 125) | 채도 1.03~1.07배, 색상 이동 4.5° 이내                                                                                     | 거의 그대로(0.99~1.02배)                    | 약한 따뜻한 틸트뿐이다. 무해하지만 "현상한 사진" 같은 변화는 없다. 검정에 빨강만 4 남는다                                                                                                      |

Figma와 맞추려고 잰 곡선이라 Figma 대조 시험(`e2e/figma-parity.spec.ts`)은 통과한다. 여기서 문제
삼는 것은 맞춘 대상, 곧 Figma의 이미지 보정 자체가 내는 결과다.

## 3. 질문별 답

| 질문                          | 답                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 피부가 주황·회색으로 뜨나     | `flash`에서 어두운 피부가 주황 쪽으로 진해진다(채도 1.18배, 색상 75°). 나머지 컬러 톤은 문제없다. 회색으로 뜨는 톤은 없다                      |
| 하이라이트가 날아가나         | 네 톤 모두 숄더가 없다. `mono`·`flash`·`film`은 흰색이 255에 닿고, `sepia`는 225부터 평평하다. 톤 없는 7종은 카메라가 날린 그대로다            |
| 그림자가 탁한가               | `sepia`만 그렇다(검정 46). 나머지는 검정이 0~4다                                                                                               |
| 채도만 올린 싼 느낌인가       | `flash`가 그렇다. 빨강 1.07배, 초록 1.10배                                                                                                     |
| 틀 색과 충돌하나              | 톤이 틀 색을 모른다. 색 처리 없는 사진이 와인색(#843F48)·남색(#222B3C)·세이지(#969F7F) 틀에 그대로 올라간다. 충돌이라기보다 **맞춘 적이 없다** |
| 미리보기와 결과물 색이 다른가 | **다르다(4절).** 틀 고르기·옵션 화면의 견본은 같은 합성기를 써서 결과와 같다. 촬영 화면과 확인·고르기 화면은 톤 없이 보인다                    |
| 그레인                        | 없다. 틀 배경 그림의 질감만 있고 사진에는 입자가 없다                                                                                          |

## 4. 미리보기 ≠ 결과

톤이 있는 틀 8종에서 손님은 촬영 화면(카메라 영상)과 확인·고르기 화면(찍은 컷)을 **컬러 원본으로**
본다. 흑백·세피아·플래시 결과는 사진을 다 고른 뒤 동의 화면의 완성본에서 처음 나온다. "미리보기 =
결과" 원칙은 자르기와 좌우 반전에만 지켜지고 색에는 지켜지지 않는다.

이번 작업은 이 부분을 고치지 않았다. 새 룩도 합성 단계에서 입힌다(틀 견본과 최종 합성은 같은
셰이더·같은 수치). 촬영 화면에 룩을 실시간으로 입히는 일은 성능 문제라 범위 밖이고, 다음 과제다.

## 5. 살릴 것 · 고칠 것 · 버릴 것

**살릴 것**

- 구조: 틀이 톤을 데이터로 갖고(`photoTone`), 합성기가 칸 크기에서 한 번 적용한다. 새 룩도 같은
  자리(`composeFrame`의 `grade`)에 들어간다.
- `ctx.filter`를 쓰지 않는 원칙. Safari 15에 없다.
- 틀 고르기·옵션 화면의 견본을 결과와 같은 코드로 그리는 것.
- 흑백의 선형광 휘도 계산. 방향은 맞다. 곡선과 채널 비중만 더한다.
- 톤 4종 자체. WebGL이 안 되는 기기의 대체 경로로 그대로 남는다.

**고칠 것(개선판을 후보에 넣었다)**

| 기존           | 문제                                    | 개선판     | 무엇을 바꿨나                                                                                         |
| -------------- | --------------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------- |
| 흑백 `mono`    | 탈색만 함, 숄더 없음, 그레인 없음       | **Ink**    | 빨강 비중을 높인 채널 믹스, S자 곡선, 종이 흰색(249)·잉크 검정(5), 은은한 그레인                      |
| 세피아 `sepia` | 검정 46으로 뿌옇고 양 끝이 잘림         | **Walnut** | 검정 (14, 6, 2), 흰색 (254, 243, 228)까지 계조를 살리고, 그림자는 깊은 갈색·밝은 곳은 종이색으로 조색 |
| 플래시 `flash` | 피부가 주황으로 진해지고 빨강·초록이 튐 | **Flash**  | 밝기 곡선과 색을 분리. 피부 색상 이동 2.1° 이내, 빨강·초록 채도 1배 이하, 숄더 추가                   |
| 컬러 `film`    | 변화가 거의 없음                        | **Linen**  | 따뜻한 인물 톤. 낮은 대비, 하이라이트 롤오프, 피부 채도 보호                                          |

**버릴 것**

- 지금 당장 지우는 코드는 없다. 기능 플래그가 꺼져 있는 동안 부스는 기존 톤으로 그대로 돈다.
- 룩을 확정해 플래그를 켜면 `sepia`의 뜬 검정(46)과 `flash`의 채널별 곡선은 물러나야 한다. 그때
  Figma 시안의 해당 틀 예시와 `docs/FIGMA_PARITY.md`의 기준도 함께 바꿔야 한다(Figma가 답이라는
  규칙 때문에 코드만 바꿀 수 없다).

## 7. 이 감사가 확인하지 못한 것

- **실제 iPad mini 4 전면 카메라의 사진**으로는 재지 못했다. 위 수치는 기준 색과 합성 샘플 기준이다.
  그 카메라의 화이트밸런스, 노이즈, 다이내믹 레인지가 결과를 좌우한다.
- 현장 조명(전구·LED의 종류와 연색성)을 모른다. 연색성 낮은 LED 아래의 피부는 필터로 못 고친다
  (시장조사 5절).
- 톤 없는 틀의 "원본"이 실제로 어떤 색인지는 현장 조명과 카메라에 달려 있다.
