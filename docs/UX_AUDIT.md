# UX 감사 — FOLLOW THE LIGHTS 2.0 (2026-11-08)

기준: 코드와 헤드리스 Chromium E2E. **실제 터치 화면·어르신 사용자 시험은 하지 않았다** — 사용성은
"미검증"이다. WCAG 2.2 AA는 아래 항목별로 코드에서 확인한 것만 적는다(전문 감사 도구·스크린리더
실기기 시험은 하지 않음).

## 1. 기존 문제 (2.0 이전 코드에서 확인)

## 2. 바꾼 것

- **첫 화면 두 갈래** (U1): "📸 여기서 사진 찍기"(금색) / "📱 내 사진으로 참여하기" 같은 크기의 큰 카드,
  아래에 "기본 화면 / 가+ 쉬운 화면" 전환과 도움말. 제출이 멈춘 동안 두 번째 카드는 비활성 + 이유 표시.
- **모든 화면 공통 하단 버튼** (U2, U4): ← 처음으로 · ? 도움말 · 가+ 쉬운 화면. 촬영 카운트다운
  중에는 숨김(누를 것도, 흩어질 것도 없게). "처음으로"는 사진이 사라질 화면에서만 확인 창
  ("지금까지 찍은 사진은 지워지고 저장되지 않아요" · 계속 찍을게요 / 처음으로 갈게요).
- **idle 예고** (U3): 15초 전부터 하단에 "N초 뒤 처음 화면으로 돌아가요 · 계속할게요".
- **도움말 창** (U4): QR 찍는 법, 저장하는 법, 카메라가 안 될 때, 도우미 부르기. 쉬운 말, 아이콘+글자.
- **포커스 표시** (U7): 버튼·링크·입력에 4px 금색 외곽선 (`:focus-visible`).
- **대화상자 접근성**: `role="dialog"`, `aria-modal`, 제목 연결, 열면 첫 버튼으로 포커스, Tab 순환,
  Esc·바깥 누르면 닫힘, 닫으면 원래 자리로 포커스.

## 3. 쉬운 모드 (D67)

나이를 묻거나 사람을 분류하지 않는다. 누구나 첫 화면 또는 모든 화면 하단에서 켜고 끈다. 관리자 →
설정 → "부스 시작 화면"이 다음 방문객의 기본값이다(감사 기록).

| 항목              | 기본                | 쉬운 화면                             |
| ----------------- | ------------------- | ------------------------------------- |
| 제목 글자         | 28–56px             | 34–76px                               |
| 안내 글자         | 18–28px, warm 90%   | 22–38px, glow 100% (대비 13.4–18.4:1) |
| 캡션              | ink-400 (4.5–6.1:1) | #d5d8e6 (10.0–13.8:1)                 |
| 주 버튼           | ≥ 64px              | ≥ 80px, 26–44px 글자                  |
| 하단 공통 버튼    | ≥ 56px              | ≥ 76px, 굵은 테두리                   |
| 촬영 전 틀 고르기 | 있음                | 없음 (촬영 후 내 사진으로 고름)       |
| 카운트다운        | 3초                 | 5초                                   |
| 자동 처음으로     | 90초                | 180초 (+15초 예고)                    |
| 진행 표시         | "3 / 7 ●●●○○○○"     | "2단계 · 사진 확인" + 막대            |
| 첫 화면 설명      | 두 줄               | 한 줄씩 줄임                          |

같은 상태 머신·업로드 큐·동의 규칙을 쓴다(중복 구현 없음). 사진 수와 틀 칸 수가 맞지 않으면 완성
버튼이 동작하지 않는 규칙도 같다.

쉬운 모드 흐름(실제 순서): ① 사진 찍기/내 사진 보내기 → ② 촬영 준비 → ③ 촬영 → ④ 사진 확인 →
⑤ 사진 꾸미기(틀) → ⑥ 사진 고르기 → ⑦ 미디어월 참여 → ⑧ 휴대폰으로 받기 → 완료.
요구 문서의 "고르기 → 꾸미기" 순서와 다르다: 기존 흐름(D65)은 틀을 먼저 정해야 몇 장을 고를지
알 수 있어서 이 순서를 유지했다.

음성 안내: 검토만 하고 만들지 않음 — 브라우저별 음성 품질 차이, 행사장 소음, 도우미가 더 낫다.

## 4. 휴대폰 업로드 화면

단계 표시(1. 사진 고르기 · 2. 확인하고 보내기 · 3. 운영팀 확인), 미리보기 = 보낼 결과(돌리기·자르기
반영), 동의 체크 전 "보내기" 비활성, 진행 막대(`role="progressbar"`), 오류마다 무엇을 하면 되는지,
"받았어요"와 "아직 미디어월에 나온 것은 아니에요"를 분리, QR 시간이 지나면 그 자리에서 안내.

## 5. 관리자

- 대기열 필터(전체/현장 촬영/휴대폰 사진), 카드에 출처 배지, 개요 타일에 출처별 건수.
- E2E에서 휴대폰 크기(Pixel 7)로 개요·검수·설정·사진 화면에 가로 스크롤 없음을 확인.

## 7. 실기기에서 꼭 볼 것 (미검증)

- 어르신·처음 쓰는 사람이 설명 없이 첫 화면을 이해하는지, 쉬운 화면 버튼을 찾는지
- 실제 터치 모니터/iPad에서 하단 버튼과 스태프 도움 모서리(왼쪽 위 3초)가 겹치지 않는지
- iPhone Safari·Android Chrome에서 휴대폰 업로드(HEIC 포함), 실제 LTE 속도
- 휴대폰 QR 인식 거리, 미디어월 동의 문구를 정확히 이해하는지
