## 1. 다시 재는 법

```bash
# 결과물 15종 + 화면 4개 (Chromium). 비교 그림과 숫자를 docs/screenshots/figma-parity/ 에 다시 쓴다.
PARITY_SAVE=1 npx playwright test e2e/figma-parity.spec.ts e2e/figma-parity-screens.spec.ts

# WebKit (Safari 엔진): 이미 떠 있는 부스 서버(e2e/env.ts 환경)를 쓴다.
PW_ENGINE=webkit npx playwright test -c playwright.dev.config.ts e2e/figma-parity.spec.ts e2e/figma-parity-screens.spec.ts
```

- 기준 그림: `tests/fixtures/figma-parity/` (`ref-<틀>.webp` = Figma 노드 2배 내보내기, `photo-<틀>-<n>.webp` =
  그 노드의 예시 사진을 필터 없이 자른 것, `screen-<화면>.webp` = 768 × 1024 화면).
- 재는 값: 픽셀마다 CIEDE2000 색차(ΔE00)를 구해 **ΔE00 > 5인 픽셀의 비율**을 본다
  (`tests/parity/compare.ts`, 계산식 검증은 `tests/unit/parity-compare.test.ts`).
- 결과물은 부스의 실제 합성 코드(`composeFrame`)를 브라우저 안에서 2배로 돌려 비교한다.
- Figma나 코드가 바뀌면: Figma에서 노드를 2배 PNG로 다시 내보내 기준 그림을 갈고 위 명령을 돌린다.
  Figma 원본은 고치지 않는다. 내보내기용 임시 복제를 만들었다면 끝나고 지운다.

### 저장소의 기준 그림은 압축본이다

`tests/fixtures/figma-parity/`의 결과물 기준 그림과 예시 사진은 WebP(손실 압축)라서 그 자체가 차이를 조금 만든다. 그래서 같은 코드도
압축본으로 재면 값이 더 크게 나온다(잰 값 최대 약 0.8 %, 기준 1 % 안. 민감한 3종은 품질을 높여 넣었다). 화면 4개의 기준 그림은 무손실 WebP라 이 문제가 없다(폴더 전체 약 17 MB). 위 표는 무손실 PNG로 잰 값이고, 무손실 PNG는 용량(약 150 MB)
때문에 저장소에 넣지 않았다. `PARITY_REF_DIR=<무손실 PNG 폴더>`를 주면 그쪽으로 잰다.
