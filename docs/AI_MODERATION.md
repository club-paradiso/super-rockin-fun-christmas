# AI-assisted photo review (D95)

상태 표기는 `docs/STATUS.md`와 같다: **구현됨 / 검증됨 / 미검증 / 막힘**. 이 문서는 기술 담당용이다.
봉사자용 안내는 `docs/STAFF_GUIDE.md`.

**한 줄 요약.** 미디어월 동의를 받은 사진을 AI가 먼저 보고, 명백히 문제없는 것만 자동 승인한다. 그 밖의
모든 경우(문제 있어 보임, 모르겠음, 오류, 시간 초과, 한도 초과, 설정 없음)는 지금처럼 사람이 본다.
**기본값은 꺼짐**이고, 켜는 것은 사람이 하는 세 단계다(8절).

> **2026-11-15에 실제 Cloudflare Workers AI를 호출해 평가했다**(사용자가 계정과 토큰을 만들었다).
> 합성 글자 카드와 위키미디어 커먼스의 공개 라이선스 사진만 썼고 방문객 사진은 쓰지 않았다. 결과는 2.3절.
> 그 평가에서 **4컷을 통째로 보내면 한 컷의 손가락 욕·피 분장을 놓친다**는 것이 드러나, 컷마다 따로
> 보내도록 바꿨다(D97). 2.1절의 다른 공급자 조사는 여전히 문서·검색 발췌 기준이다. **실제 Vercel
> 배포, 실제 부스 사진, 하루 무료 한도의 정확한 동작은 아직 미검증이다.**

## 3. 안전 정책 (Phase E)

정책은 코드 두 곳에만 있다: 무엇을 묻는가 `lib/moderation/prompt.ts`, 답을 어떻게 읽는가
`lib/moderation/policy.ts`. 공급자의 일반 콘텐츠 정책에 기대지 않는다.

| 범주 코드          | 뜻                                              | 모델이 볼 수 있나                |
| ------------------ | ----------------------------------------------- | -------------------------------- |
| `sexual`           | 성행위, 선정적 포즈·접촉                        | 대체로 가능                      |
| `nudity`           | 노출, 의도적으로 보인 속옷                      | 대체로 가능                      |
| `violence`         | 피, 심한 부상, 사람을 겨눈 무기                 | 대체로 가능                      |
| `hate`             | 혐오 상징·구호, 특정 대상 위협                  | 유명 상징은 가능, 변형은 놓침    |
| `gesture`          | 욕설 손동작                                     | 크게 보이면 가능, 작으면 놓침    |
| `offensive_text`   | 읽을 수 있는 욕설·비방(한글·영어, 손글씨 포함)  | 큰 글자는 가능. 은어·초성은 놓침 |
| `other`            | 그 밖에 화면에 맞지 않는 것                     | 불확실 → 사람 판단               |
| `provider_blocked` | 공급자가 사진 확인 자체를 거부함(어댑터가 붙임) | —                                |

판정 규칙:

- **SAFE**는 전부 맞아야 한다: `verdict: "safe"`, 범주 없음, 사진 속 글자가 검수자에게 지시하지 않음.
- **UNSAFE**: `verdict: "unsafe"` + 범주 하나 이상. 비공개로 두고 검수 대기 맨 앞에 "AI 주의"로 보인다.
  **자동 반려·삭제는 하지 않는다.** 잘못 짚은 가족사진을 지우면 되돌릴 수 없기 때문이다.
- **UNCERTAIN**: 그 밖의 전부. 모르겠음, 앞뒤 안 맞는 답, 사진 속 글자가 지시문.
- 형식이 조금이라도 다른 답(빠진 필드, 모르는 값, 설명 문장 섞임, 잘린 JSON)은 답으로 치지 않는다 → 실패 → 사람.

부당한 반려를 줄이는 장치: 프롬프트가 평범한 가족·아이·종교 이미지·성탄 장식·V·손하트·무해한 글자를
"정상"이라고 명시한다. QR·웹 주소만으로는 표시하지 않는다.

하지 않는 것: 얼굴 인식, 신원·나이·성별·인종·종교 추정. 프롬프트가 금지하고, 응답 형식에 사람을 묘사할
자리가 없다(자유 문장 필드가 없다). 저장되는 것은 범주 코드뿐이다.

**사진 속 글자·QR는 데이터다.** 따르지 않는다. 글자가 검수자나 AI에게 지시하면 모델이
`text_instructions: true`를 내고, 그러면 다른 답과 상관없이 사람에게 간다. QR을 해독하는 코드는 넣지
않았다(해독한 내용을 처리할 이유가 없고 공격면만 늘어난다).

## 4. 구조 (Phase C, D, G)

### 4.1 흐름

```
부스 동의 화면 ── "네" ──────────────────────────────────► POST /api/photos/consent
                                                              │ NONE → PENDING (기존 전이, 감사 기록)
                                                              │ 모드가 auto이고 공급자 설정이 있으면
                                                              ▼
                                                 ftl_ai_enqueue: ai_status NONE → QUEUED
                                                              │ 응답을 보낸 뒤 바로 한 번 시도 (after)
                                                              ▼
            ftl_ai_claim (한 호출자만, 45초 임대, 시도 횟수 +1)
                 │
                 ├─ 사진 파일 읽기 → 틀의 슬롯 좌표로 컷마다 축소본(D97: 여러 컷이면 640px,
                 │   한 컷 틀이면 1024px, JPEG, 메타데이터 없음). 틀을 모르면 보내지 않고 사람에게
                 ├─ 하루 한도를 컷 수만큼 차감 (ftl_ai_budget_take). 모자라면 한 컷도 안 보냄
                 ├─ 컷마다 공급자 호출, 동시에 (각 제한 시간 8초, 강제 종료)
                 ├─ 컷마다 정책 판정 (policy.ts) → 한 컷이라도 주의면 UNSAFE, 한 컷이라도 답이
                 │   없으면 재시도/FAILED, 한 컷이라도 보류면 UNCERTAIN, 전부 safe일 때만 SAFE
                 ▼
            ftl_ai_complete (한 트랜잭션)
                 ├─ SAFE + 아직 PENDING + 동의 있음 + 삭제 안 됨 + 모드 auto + 임대 일치
                 │        → APPROVED, 감사 기록 ai_approve (actor: system)
                 └─ 그 밖 전부 → PENDING 그대로. ai_status만 기록
```

검수 상태(`moderation_status`)와 AI 상태(`ai_status`)는 다른 열이다. 앞은 결정, 뒤는 기계의 의견이다.

| `ai_status` | 뜻                                              | 사진은                    |
| ----------- | ----------------------------------------------- | ------------------------- |
| `NONE`      | AI에 보낸 적 없음                               | 사람 검수                 |
| `QUEUED`    | 대기 중이거나 확인 중                           | 비공개                    |
| `SAFE`      | 문제없다고 봄                                   | 조건이 맞으면 자동 승인됨 |
| `UNSAFE`    | 주의 표시                                       | 비공개, 사람 검수 맨 앞   |
| `UNCERTAIN` | 판단 보류                                       | 비공개, 사람 검수         |
| `FAILED`    | 확인 못 함(시간 초과·장애·읽을 수 없는 답)      | 비공개, 사람 검수         |
| `SKIPPED`   | 일부러 안 보냄(한도·수동 전환·사람이 먼저 처리) | 사람 검수                 |

### 4.3 공급자 교체

어댑터는 인터페이스 하나다(`lib/moderation/types.ts`):

```ts
interface ModerationProvider {
  readonly id: string;
  readonly model: string;
  analyze(image: ModerationImage, signal: AbortSignal): Promise<ProviderAssessment>;
}
```

받는 것은 축소본과 중단 신호뿐이다. 사진 행·id·세션·토큰은 어댑터에 전달되지 않는다. 새 공급자는
`lib/moderation/providers/`에 파일 하나, `lib/moderation/server.ts`의 `createProvider`에 한 줄이다.
저장·동의·벽 코드는 건드리지 않는다.

들어 있는 어댑터: `chat-vision.ts`(OpenAI 형식 `chat/completions`. Cloudflare Workers AI와 호환 서비스),
`gemini.ts`(유료 등급 전용), `mock.ts`(시험용. 실제 배포에서는 설정이 거부).

### 4.5 보조 공급자 (D98)

1차 공급자가 사진을 받을 수 없을 때만 2차(보조) 공급자가 같은 사진을 본다. 예: 1차 Cloudflare 무료
한도, 2차 맥북의 Ollama를 Cloudflare Tunnel(https)로 연결.

| 상황                                                                  | 처리                                                                                                                                                                           |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1차의 하루 한도(`AI_MODERATION_DAILY_LIMIT`)가 이 서버 기준으로 다 참 | 1차를 부르지 않고 보조로. 보조 호출은 이 한도를 쓰지 않는다                                                                                                                    |
| 1차가 HTTP 429(사용량 제한·할당량 소진)                               | 같은 사진을 바로 보조로. `Retry-After`가 5분 이하면 그만큼, 없거나 길면 **다음 00:00 UTC까지** 1차를 건너뛴다(프로세스 메모리. 재시작하면 1차를 한 번 더 부르고 다시 넘어간다) |
| 1차가 한 컷이라도 UNSAFE로 봄(다른 컷이 429여도)                      | 그것이 판정이다. 보조에게 다시 묻지 않는다                                                                                                                                     |
| 1차의 시간 초과·5xx·네트워크·인증 오류                                | 기존대로(재시도·정지). 보조로 넘기지 않는다                                                                                                                                    |
| 보조가 꺼짐·시간 초과·오류·unsure·설정 없음·설정 오류                 | 사진은 PENDING. 재시도 3회 상한, 그 뒤 FAILED → 사람. 연속 3회 실패하면 1분 정지                                                                                               |

- **한 공급자가 사진 한 장 전체를 책임진다.** 보조로 넘어가면 모든 컷을 보조가 다시 본다. 판정 기록·감사
  기록의 `provider`/`model`은 실제로 답한 쪽이다(예: `openai-compatible` · `qwen2.5vl:3b`). 로그의
  `ai_review` 이벤트에 `route`(`primary`/`fallback`)와 `switchedBecause`(`daily_limit`/`rate_limited`)가 남는다.
- **승인 경로는 그대로 하나다**: `AiReviewRepository.complete` + SAFE(`ftl_ai_complete`). 보조도 같은
  프롬프트, 같은 컷별 사본, 같은 정책 파서를 쓴다. 마이그레이션 없음.
- **시간 상한**: 보조의 컷 하나는 `AI_MODERATION_FALLBACK_TIMEOUT_MS`(기본 20초), 사진 한 장 전체는
  리뷰 시작부터 `fallbackPhotoBudgetMs` 22초(`config/moderation.ts`). 30초 함수(`maxDuration`)와 45초 임대
  안에 끝나게 하려는 값이다. 넘기면 남은 컷은 보내지 않고 `timeout` → 나중에 재시도. cron 라우트는 한 번에
  한 장씩, 32초 이후로는 새 사진을 집지 않는다.
- **순차 모드**(`AI_MODERATION_FALLBACK_SEQUENTIAL=1`): 컷을 하나씩 보내고, 처음 UNSAFE나 오류에서 멈춘다
  (어차피 SAFE가 될 수 없다). 팬리스 맥북 에어의 발열·스로틀링 완화용.
- **보조 모델도 승인할 수 있다.** 3B급 로컬 모델은 2.3에서 평가한 Llama 4 Scout보다 약할 가능성이 크다.
  **켜기 전에 같은 평가(2.3)를 보조 모델로 돌린다**(1차 변수 자리에 `openai-compatible`·터널 주소·모델을
  넣고 실행). 잘못 승인이 나오면 보조를 켜지 않는다. **이 저장소에서 Ollama 모델은 평가하지 않았다(미검증).**
- **개인정보**: 보조 경로에서는 사진 컷 사본이 Cloudflare 네트워크를 거쳐 운영자의 노트북으로 간다.
  노트북이 수탁 처리 장소가 된다(5절에 추가로 적을 것). Ollama의 `OLLAMA_DEBUG`를 켜지 않는다(요청이
  로그에 남을 수 있음). 터널 주소는 Cloudflare Access 서비스 토큰으로 막기를 권한다
  (`AI_MODERATION_FALLBACK_ACCESS_CLIENT_ID`/`_SECRET`).

### 4.4 Vercel에서 대기열을 누가 돌리나

대기열은 DB에 있다(메모리 큐·버려지는 Promise에 기대지 않는다). 돌리는 쪽은 여러 겹이다.

1. **동의 직후**: 응답을 보낸 뒤 Next `after()`로 한 번 시도(Vercel에서는 `waitUntil`).
2. **평소 요청에 얹기**: 등록된 벽 화면의 피드 폴링(5초), 부스 하트비트, 부스의 확인 상태 조회(2.5초),
   관리자 개요·검수 화면. 인스턴스당 5초에 한 번, 한 번에 최대 2장.
3. **`/api/cron/ai-review`** (`Authorization: Bearer $CRON_SECRET`): 외부 스케줄러용. **`vercel.json`에는
   넣지 않았다.** Hobby 요금제는 하루 1회보다 잦은 cron을 받지 않아 배포가 실패한다.
4. **허브**: 프로세스 안 타이머(3초).

벽 화면도 부스도 관리자도 없으면 2번이 멈춘다. 그때는 기다리는 사람도 없다. 다음 요청이 오면 이어 간다.

## 5. 개인정보 (Phase F)

밖으로 나가는 것: **컷마다 축소본 한 장씩(4컷이면 요청 4번)과 고정된 영어 프롬프트.** 그 밖에는 아무것도 없다. 사진 id, 세션,
부스 이름, 행사 이름, 시각, 토큰, 저장 경로를 보내지 않는다(`tests/unit/ai-providers.test.ts`가 요청
본문을 통째로 비교한다).

축소본(`lib/moderation/image.ts`의 `prepareModerationShots`): 실제 형식 확인 → 4천만 화소 초과 거부 →
방향 적용 → 사진 모양이 틀과 같은지 확인 → 틀의 슬롯마다 잘라내기(기울어진 슬롯은 그것을 감싸는 상자) →
긴 변 640px(한 컷 틀은 1024px) → JPEG 재인코딩. 틀 그림(우리가 인쇄한 부분)은 보내지 않는다. EXIF·GPS·ICC·주석이 남지 않는다(`tests/unit/ai-image.test.ts`). 원본은 그대로 비공개
버킷에 있다.

기록: 로그에는 결과 코드·시도 횟수·소요 시간만 남는다. 사진 바이트, 요청 본문, 공급자 응답 본문, 범주는
로그에 쓰지 않는다. 공급자 오류 본문은 읽지도 않는다. API 키는 서버 환경 변수에만 있고 주소가 아니라
헤더로 보낸다.

**동의와 안내 (D96, 사용자 결정 2026-11-14).** 부스는 AI 확인을 **따로 안내하지 않는다.** 처음에는 동의
화면에 "외부 AI 서비스로 보내 확인한다"는 줄을 넣고 그 줄을 본 "네"만 AI로 보냈는데(D95), 사용자가
"AI에 대해 굳이 말할 필요는 없다"고 결정해 뺐다. 지금은 자동 확인이 켜진 동안 미디어월에 "네"라고 한
사진이 모두 AI로 간다. 대신 동의 화면의 작은 글씨에 **"화면에 어울리지 않는 사진은 운영팀이 숨길 수
있어요."** 한 줄을 모드와 상관없이 항상 보여 준다(이 줄은 Claude가 썼고 사용자 확인 전이다, D76).

이 결정으로 아래 법적 문제의 무게가 커졌다. 방문객은 사진이 해외 사업자에게 전송된다는 사실을 화면에서
알 수 없다. 켜기 전에 교회가 근거(처리방침 공개, 별도 동의, 또는 보내지 않기)를 정해야 한다는 점은
그대로다. 코드가 대신 정해 주지 않는다.

**사람이 판단해야 하는 법적 문제.** 법률 자문이 아니다. 확인한 조문은 「개인정보 보호법」(법률 제21445호,
2026-09-11 시행)이다.

| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 제28조의8 제1항·제2항 | 개인정보의 국외 제공·처리위탁·보관은 원칙적으로 금지. 별도 동의(이전 항목, 국가·시기·방법, 이전받는 자, 이용 목적·보유 기간, 거부 방법을 미리 알림) 등 예외에 해당해야 함 | 후보 공급자는 모두 해외 사업자다. 얼굴이 나온 사진은 개인정보다. **부스는 AI 전송을 아예 안내하지 않는다(D96).** 어느 예외에 해당하는지, 문구·처리방침을 어떻게 할지 교회가 정해야 한다 |

## 6. 운영 모드와 실패 처리 (Phase H, K, L)

새 모드 체계를 만들지 않고 기존 스위치에 하나를 더했다.

| 요청한 모드        | 실제 설정                                                       | 화면                              |
| ------------------ | --------------------------------------------------------------- | --------------------------------- |
| AUTO_MODERATION    | `moderationMode: "auto"` (+ 공급자 설정 있음)                   | 개요·검수의 "사진 확인 방식" 카드 |
| MANUAL_REVIEW      | `moderationMode: "manual"` (기본값)                             | 같은 카드                         |
| SUBMISSIONS_PAUSED | 기존 `pauseSubmissions` ("미디어월 게시 신청 중지")             | 긴급 제어                         |
| EMERGENCY_BLACKOUT | 기존 `pauseWall` ("미디어월 일시정지") 또는 `showHoldingScreen` | 긴급 제어                         |

모드 변경은 스태프 세션 + 같은 출처 + JSON이 필요하고(`staffRoute`), `update_settings` 감사 기록에 전후
값이 남는다. 공급자 설정이 없는 서버에서 `auto`를 켜려 하면 409로 거부한다.

실패했을 때:

| 상황                             | 처리                                                                                                     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 시간 초과(기본 8초)              | 강제 중단. 5초 뒤, 30초 뒤 다시. 사진당 총 3회. 그래도 안 되면 FAILED → 사람                             |
| HTTP 429                         | `Retry-After`만큼(최대 5분) **모든 호출을 멈춘다.** 멈춘 동안은 사진을 집지 않아 시도 횟수를 쓰지 않는다 |
| HTTP 5xx·네트워크 끊김           | 다시 시도. 연속 3회 실패하면 1분 멈춤                                                                    |
| HTTP 401·403                     | 다시 시도 안 함. 5분 멈춤. 관리자 화면에 "인증 실패"                                                     |
| 읽을 수 없는 답, 그 밖의 4xx     | 다시 시도 안 함 → FAILED → 사람                                                                          |
| 공급자가 사진을 차단             | UNSAFE(`provider_blocked`) → 사람                                                                        |
| 사진 파일 없음·형식 이상·너무 큼 | 공급자 호출 없이 FAILED → 사람                                                                           |
| 하루 한도 도달                   | 호출 없이 SKIPPED → 사람. 관리자 화면에 경고                                                             |
| DB 오류로 결과 기록 실패         | 승인 없음. 임대가 끝나면 다시 집음                                                                       |
| 서버리스 함수가 중간에 죽음      | 임대가 끝나면 다시 집음(시도 횟수는 이미 차감)                                                           |
| AI 설정 값이 틀림                | **서버는 계속 뜬다.** AI만 꺼지고 관리자 화면과 로그에 이유가 나온다                                     |

어느 경우에도 부스는 멈추지 않는다. 확인은 응답을 보낸 뒤에 돌고, QR은 이미 화면에 있다.

**비용 보호.** `AI_MODERATION_DAILY_LIMIT`(기본 300)로 하루 호출 수를 제한한다. **호출은 컷 단위**라
4컷 사진 한 장이 4를 쓴다. 사진당 3회 시도 상한, 임대로 중복 호출 방지, 연속 실패 시 정지. 유료 전환·결제·GPU 준비를 하는 코드는 없다. 사용량은 **이 서버가 센
추정치**다. 공급자의 실제 잔량을 읽는 API는 없다(Gemini는 없음을 확인 [A], Cloudflare는 미확인).
화면에도 "추정치"라고 적는다.

용량(2026-11-15 측정, Llama 4 Scout, 응답의 `usage.neurons`): 640px 컷 한 번에 약 24~33 neurons,
1024px 한 장에 약 61. **4컷 사진 한 장이 약 97~130, 6컷이 약 160~190, 한 컷 틀이 약 61 neurons.** 무료
한도가 하루 10,000 neurons [S]라면 4컷 기준 **하루 약 75~100장**이다. 기획안의 부스당 시간당 20건에
동의율 60%를 가정하면 하루 6시간에 약 70장이라 빠듯하다. 한도를 넘는 사진은 사람이 본다.
`AI_MODERATION_DAILY_LIMIT`은 컷 수 기준이므로 **280**을 권한다(280컷 × 약 33 ≈ 9,200 neurons).
**무료 한도를 넘기면** Cloudflare는 HTTP 429와 오류 코드 4006("you have used up your daily free
allocation of 10,000 neurons")을 준다. `Retry-After`는 없다(2026-11-15, 평가로 한도를 다 쓴 뒤 확인).
이 서버는 그것을 `rate_limited`로 보고 호출을 1분씩 멈추며, 사진은 세 번 시도한 뒤 사람에게 간다.
보조 공급자가 설정되어 있으면(D98, 4.5절) 대신 그 사진부터 보조로 넘기고 00:00 UTC까지 1차를 건너뛴다.
한도는 00:00 UTC(한국 시간 09:00)에 초기화된다 [S]. 첫날 대시보드의 사용량과 Cloudflare 콘솔을 비교한다.

| 공급자 응답 시간, 사진 한 장(컷 동시 호출)            | 중앙값 2.2초 · 최대 3.4초 (n=20) | 2026-11-15, Cloudflare Llama 4 Scout, 이 작업 환경에서. 첫 호출은 13초(모델 깨우기)였다 |
| 승인 → 벽에 처음 뜸                                   | 기존 값 그대로                   | 벽 폴링 5초 + 회전 순서. 이번에 바꾸지 않았다                                           |

"1~3초"는 목표로만 본다. 구조상 하한은 공급자 응답(측정 약 2초) + 벽 폴링(최대 5초)이다.
안전을 줄여 속도를 올리는 길은 넣지 않았다.

Vercel 호환성: Node 런타임, 추가 의존성 없음(`sharp`는 이미 있음). AI 호출이 얹히는 라우트에
`maxDuration = 30`(cron 60). 요청 본문은 컷 하나의 축소본 base64 약 40~120KB. 벽 피드·이미지는 `no-store`라
승인 전 사진이 캐시로 새지 않는다. **실제 Vercel 배포에서는 돌려 보지 않았다(미검증).**

## 9. 되돌리기

가장 빠른 순서대로. 어느 것도 사진을 잃지 않는다.

1. **관리자 화면**: 검수 → "사람이 모두 확인하기로 바꾸기". 즉시. 대기 중이던 사진은 검수 대기로 온다.
2. **환경 변수**: `AI_MODERATION_PROVIDER`를 지우고 재배포. 외부 호출이 불가능해진다. 보조만 끄려면
   `AI_MODERATION_FALLBACK_PROVIDER`를 지우거나 노트북의 터널을 끈다(사진은 사람에게 간다).
3. **코드**: PR을 되돌린다. 마이그레이션은 그대로 두어도 된다(추가된 열·함수는 옛 코드에 영향이 없고,
   옛 `ftl_settings_update` 서명이 남아 있다).
4. AI가 승인한 사진을 다시 보려면: 검수 → "AI 승인" 구역에서 하나씩 숨기거나, 급하면 "미디어월 일시정지".
