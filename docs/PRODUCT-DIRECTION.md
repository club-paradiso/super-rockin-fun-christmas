## 0. 조사 방식에 대한 참고

두 레퍼런스 사이트(`sound.gojaehyun.com`, `handvox.gojaehyun.com`)는 이 실행 환경의 네트워크 정책에 막혀 직접 접속하지 못했습니다. 대신 **두 프로젝트의 공개 소스코드를 직접 읽었습니다** (`Gojaehyeon/soundgo`, `Gojaehyeon/handvox`, MIT). 라이브 체험보다 오히려 정확합니다 — 음악 모델, 제스처 매핑, 상태 관리를 추측이 아니라 코드 레벨에서 확인했습니다. 아래 분석의 모든 주장은 실제 코드 라인에 근거합니다.

**`silent-night-conductor.html`은 이 세션에 첨부되지 않았습니다.** 저장소는 빈 상태였고 첨부 디렉터리도 비어 있었습니다. 따라서 4장의 프로토타입 비평은 **당신이 프롬프트에서 서술한 사양 + 이 아키타입이 구조적으로 갖는 문제**를 근거로 작성했으며, 코드 레벨 비평이 아닙니다. 해당 부분은 명시적으로 표시했습니다. 파일을 다시 첨부해 주시면 코드 레벨 비평으로 교체하겠습니다.

# 1. Executive Verdict

**결론 세 줄:**

1. **Silent Night Conductor는 제품이 될 수 없습니다.** "지휘하면 다음 음이 난다"는 재생 버튼을 몸으로 누르는 것입니다. 30초 뒤에 할 일이 없습니다.
2. **Soundgo와 Handvox의 진짜 빈틈은 화성이 아니라 시간(TIME)입니다.** 두 제품 모두 **리듬 엔진이 존재하지 않습니다.** 공유 클럭이 없으므로 여러 사람이 함께 연주할 수 있는 기반 자체가 없습니다. 이것이 미디어월에서 이들을 그대로 쓸 수 없는 이유이며, 동시에 우리의 기회입니다.
3. **권장 방향: AFTERGLOW** — 움직임이 빛의 궤적이 되고, 그 궤적이 박자에 맞춰 **스스로 반복되는 루프**가 되며, 여러 사람의 루프가 쌓여 하나의 합주가 되는 구조.

**Christmas 구조는 B(범용 엔진 + Christmas World)가 맞습니다.** 단, 당신의 의견에 맞춘 것이 아니라 이 메커니즘이기 때문에 맞습니다: *여러 사람의 작은 빛이 모여야 하나의 곡이 완성된다*는 것은 크리스마스 스킨이 아니라 **인터랙션 규칙 그 자체**입니다. 성경 구절도 눈송이도 필요 없습니다. B가 아니라 A(제품 자체가 Christian product)를 택하면 이 의미가 오히려 약해집니다 — 설명이 이미지를 대체하기 시작하기 때문입니다.

# 2. Soundgo Deconstruction

*근거: `Gojaehyeon/soundgo` `index.html` 942줄 전체*

### Core Loop
왼손 = 코드 휠(12분할 원판)에서 루트 선택. 오른손 = 멜로디. 두 모드:
- `melody+chord`: 오른손 X축 = 건반 위 음높이, Y축 = 음량, 핀치 = 게이트. 왼손 핀치 = major/minor 토글.
- `two-hand-chord`: 왼손 루트 휠 + 오른손 퀄리티 휠(8분할: maj, maj7, 7, sus4, m, m7, dim, aug).

### Musical Model — 가장 중요한 발견
```
grep -niE "transport|tempo|bpm|schedule|quantiz|beat" soundgo.html  →  결과 없음
```
**리듬 엔진이 아예 없습니다.** `Tone.Oscillator`를 `osc.start()`로 켜 두고 게인만 조절합니다. 즉 Soundgo는 **양자화된 테레민 + 지속음 패드**입니다. 음표(note event)라는 개념이 없고, 시작도 끝도 박자도 없습니다.

결과:
- 그루브가 없다 → 몸이 움직이지 않는다
- 시간 구조가 없다 → 음악이 어디로도 가지 않는다
- **공유 클럭이 없다 → 두 사람이 맞출 대상이 없다**

### 다인 처리 — 구조적으로 불가능
```js
} else if (hands.length >= 2) {
  const sorted = [...hands].sort((a, b) => a[0].x - b[0].x);
  pitchHand = sorted[0];
  leftHand  = sorted[1];
}
```
손을 **X좌표로 정렬해 역할을 배정**합니다. 두 사람이 서면 A의 손과 B의 손이 한 사람의 양손으로 취급됩니다. 다인 개념이 코드에 존재하지 않습니다. 미디어월에 4~8명이 서는 순간 완전히 무너집니다.

### Onboarding
전체 안내 문구가 이것뿐입니다:
```js
ko: { desc: "두 가지 모드가 있어요.\n재미있게 사용해주세요!" }
```
**설명이 거의 없는 것은 강점입니다.** 그런데 그 다음 화면이 `maj7 / sus4 / dim / aug`가 적힌 원판입니다. 즉 설명은 없애고 **음악 이론은 화면에 그대로 남겨 두었습니다.** 7세 아동에게 `dim`은 의미가 없습니다.

### Visual Feedback
```js
drawHand(pitchHand, '#4a9eff', qLabel);   // 손 스켈레톤 + "QUALITY" 텍스트 라벨
drawHand(leftHand, ..., 'Minor C');       // "Minor C" 라벨
```
매 프레임 `ctx.clearRect()` → **화면에 기억이 없습니다.** 내가 한 행동의 흔적이 1프레임도 남지 않습니다. 스켈레톤 + 라벨 + 휠 = 정확히 "개발자용 시각화"입니다.

### Strengths
- 첫 소리까지의 마찰이 거의 0 (접속 → 카메라 → 소리)
- `stabilizeSlice()` 히스테리시스로 슬라이스 선택이 떨리지 않음 — 좋은 엔지니어링
- 휠 안쪽에 OFF 존이 있어 "손을 내려놓을 곳"이 있음 — **차용할 것**
- 15개 언어 i18n

### Weaknesses
- 리듬/시간 없음 → 30초 이후 할 일 없음
- 다인 불가
- 음악 이론이 UI 표면에 노출
- 시각적 잔상 없음 → 표현의 축적이 없음
- `canvas.width = window.innerWidth`를 매 프레임 실행 (버퍼 재할당)

### What to Borrow
1. **0마찰 진입** — 랜딩에서 첫 소리까지 한 번의 클릭
2. **OFF 존 / 쉬는 자리**의 존재
3. 선택값 히스테리시스 (미디어월에서는 필수)
4. 손을 들면 소리, 내리면 침묵이라는 **직접적 게이트**

### What NOT to Borrow
1. 화음 이름을 UI에 노출하는 것
2. 손 스켈레톤 + 텍스트 라벨 오버레이
3. 지속음만 있는 무시간 음악 모델
4. X좌표 정렬 기반 역할 배정
5. 매 프레임 전체 지우기(잔상 없음)

# 3. Handvox Deconstruction

*근거: `Gojaehyeon/handvox` `index.html`, `README.md`*

### Core Loop
마이크로 노래 → YIN 피치 검출 → 양손 손가락 개수가 화음 보이싱을 결정 → 사인파 8보이스가 목소리에 붙음. 12키 피아노에서 키를 눌러 조성을 고정.

두 모드:
- **AROUND**: 부르는 음 주변으로 다이어토닉 화음. 손가락 수 = 보이싱 복잡도 (0~4).
- **DEGREE**: 양손 합산 손가락 수 1~8 → 선택한 키의 I~VIII도 코드. 재즈 8보이싱(sub-bass, bass, root, 3, 7, 9, 5, 13).

### 뛰어난 부분 — 신호 처리
README의 시그널 체인은 진지합니다:
- 노트 전환 히스테리시스 **55 cent × 55 ms** → 비브라토에 반응하지 않음
- 피치 홀드 **1.2s** → 자음/숨 구간을 연속음으로 이음
- 4-factor VAD (RMS·band·flatness·ZCR)
- 하모니 게이트 = 손 감지 AND 피치 신뢰

**이것이 Handvox의 진짜 가치입니다: "사용자의 부정확함을 시스템이 흡수한다."** 떨리는 목소리를 그대로 따라가지 않고, 의도를 추정합니다.

### 치명적 문제 — 시작 화면
```html
<div id="gate" class="gate">
  <select id="scale-select">
    <option value="major">Major</option>
    <option value="minor">Minor</option>
    <option value="dorian">Dorian</option>
    <option value="mixolydian">Mixolydian</option>
    <option value="major_pent">Major Pentatonic</option>
```
**놀기 전에 Dorian과 Mixolydian 중에서 고르라고 요구합니다.** 그리고 HUD에는 `ROOT`, `LEVEL`, `f0 Hz`, `C major`가 상시 표시됩니다.

> **음악을 전혀 모르는 7살 어린이에게 이 인터랙션이 그대로 재미있는가?**
>
> 아니오. 두 번 막힙니다. (1) 시작 화면에서 모르는 단어를 고르라고 함. (2) "12키 피아노에서 루트를 클릭"해야 함 — 도의 위치를 모르면 불가능. 게다가 **헤드폰 필수**(스피커 사용 시 하울링)라는 조건은 미디어월에서 물리적으로 성립하지 않습니다.

### 필요한 Abstraction Layer
표현력을 잃지 않으면서 이론을 없애려면:
1. **조성 선택을 없앤다.** 세계(World)가 조성을 갖는다. 사용자는 "고요한 밤"을 고르지 C단조를 고르지 않는다.
2. **도수를 손가락 개수에 매핑하지 않는다.** 손가락 개수는 세는 행위이지 표현이 아니다. 대신 **연속적인 신체 양(높이, 속도, 거리)**에 매핑한다.
3. **화음 진행을 사용자에게 맡기지 않는다.** 시간이 진행을 굴리고, 사용자는 그 위에서 논다.

### Strengths
- 목소리라는 가장 원초적인 입력
- 사용자의 부정확함을 흡수하는 정교한 게이팅
- 음성이 있을 때만 화음이 열리는 명확한 인과

### Weaknesses
- 시작 화면이 음악 이론 시험
- HUD가 계측기
- 헤드폰 필수 → 공공 설치 불가
- 스피커로 배경음악 재생 시 미지원 → 행사장 부적합
- 역시 **리듬 없음** (드론 + 화음)
- 1인 전용

### What to Borrow
1. **히스테리시스·홀드로 부정확함을 흡수하는 철학** — 이 제품 전체의 기반이 되어야 함
2. 입력이 신뢰될 때만 소리를 여는 게이트 개념
3. "시스템이 화성을 책임진다"는 태도

### What NOT to Borrow
1. 시작 전 모드/스케일 선택
2. f0 / ROOT / LEVEL HUD
3. 손가락 개수 = 음악 파라미터
4. 마이크 의존 (공공 공간에서 붕괴)

# 4. Silent Night Conductor Critique

> ⚠️ **파일 미첨부.** 아래는 당신이 서술한 사양과 이 아키타입의 구조적 성질에 대한 비평입니다. 코드 레벨 비평이 아닙니다.

### 좋은 점
- **틀린 음이 구조적으로 나오지 않는다** — 올바른 출발점. 이 원칙은 유지.
- **여러 명을 처음부터 상정** — Soundgo/Handvox보다 앞섬.
- 지휘라는 은유는 설명이 거의 필요 없음.
- 타이밍만 다루므로 진입 장벽이 매우 낮음.

### 구조적으로 잘못된 점
1. **재생 버튼을 몸으로 누르는 것.** 곡은 이미 정해져 있고 사용자는 진행 속도만 만집니다. 만든 것이 아니라 통과시킨 것입니다.
2. **틀린 음을 없애면서 선택 자체를 없앴다.** 이것이 핵심 실패입니다. Musical Safety는 얻었지만 Agency가 0에 수렴합니다. "내가 뭘 해도 결국 고요한 밤"입니다.
3. **역할 분리는 협업이 아니다.** Melody/Bass/Harmony/Bell은 네 개의 독립 트랙입니다. A의 행동이 B의 소리를 바꾸지 않으면 Solo × 4입니다.
4. **곡이 끝나면 경험도 끝난다.** 3분 루프가 존재하지 않습니다.
5. **Christmas가 제품의 정체성이 되어버렸다.** 곡을 빼면 남는 것이 없습니다.

### Soundgo보다 나은 점 / 못한 점
- **나은 점:** 다인 상정, 시간 구조(박자) 존재, 이론이 UI에 없음
- **못한 점:** 음높이 agency 0 (Soundgo는 실제로 음을 고름), 반복 가치 낮음, 곡 종속

### Handvox보다 나은 점 / 못한 점
- **나은 점:** 사전 지식 0, 공공 공간 가능, 다인
- **못한 점:** 표현 해상도가 훨씬 낮음, 숙련 곡선 없음

### 예상 반응
- **7세:** 처음 10초 신남 → "또 뭐 할 수 있어?" → 30초 후 이탈
- **일반 성인:** 5초 안에 이해 → 곧 "내가 하는 게 맞나?" → 관망
- **음악인:** 즉시 간파. "그냥 재생 속도 조절이네."

### Media Wall 문제
- 지휘 동작은 **팔 하나**만 씁니다. 미디어월은 신체 전체와 공간을 쓸 수 있는데 낭비입니다.
- 관객(비플레이어)에게 볼거리가 약합니다 — 화면이 곡의 진행만 보여주므로.
- 사람이 없을 때의 상태가 정의되지 않습니다.

### Personal Web 문제
- 혼자서 고요한 밤을 지휘하는 것은 30초짜리 신기함입니다. 재방문 이유가 없습니다.

### Visual Design 문제
- 지휘 은유가 시각을 지배하면 "박자 표시기"가 되기 쉽습니다.
- 곡 진행 = 화면 진행이면 그것은 플레이어이지 설치물이 아닙니다.

### 살릴 것 / 버릴 것
| 살릴 것 | 버릴 것 |
| --- | --- |
| 틀린 음이 안 나오는 원칙 | 지휘 은유 |
| 공유된 박자의 존재 | 고정된 곡을 따라가는 구조 |
| 다인을 전제한 설계 | 역할 분배식 협업 |
| 신체 큰 동작 = 큰 음악 사건 | Christmas를 제품 정체성으로 삼는 것 |

# 5. Problem Definition

세 제품을 겹쳐 놓으면 빈칸이 정확히 보입니다.

| | 음높이 Agency | 시간 Agency | 다인 | 축적/기억 |
| --- | --- | --- | --- | --- |
| Soundgo | 있음 | **없음** | **없음** | **없음** |
| Handvox | 있음(이론 필요) | **없음** | **없음** | **없음** |
| Silent Night | **없음** | 있음(제한적) | 있음(병렬) | **없음** |
| **빈칸** | **있음(이론 불필요)** | **있음** | **있음(상호작용)** | **있음** |

**해결해야 할 문제:**
> 음악 지식이 0인 사람이, 설명 없이, 자기 행동으로 **실제로 다른 음악을 만들고**, 그 결과가 **사라지지 않고 쌓이며**, 다른 사람이 들어오면 **혼자서는 불가능한 일**이 일어나게 하려면 어떤 인터랙션이어야 하는가?

**핵심 통찰:** 훈련받지 않은 인간이 이미 잘하는 음악적 차원은 **화성이 아니라 시간**입니다. 걷고, 박수치고, 심장이 뜁니다. 그러므로:

> **화성은 기계가 갖는다. 시간과 공간은 사람이 갖는다. 공유된 박자가 사회적 접착제가 된다.**

# 6. Product Opportunity

Soundgo와 Handvox 이후에 만들 가치가 있는 새 인터랙션은:

> **제스처를 "연주"가 아니라 "녹음"으로 취급하는 것.**

당신의 움직임은 소리를 내는 동시에 **포착되어 루프가 됩니다.** 손을 내리면 그 궤적은 사라지지 않고, 박자에 맞춰 스스로 반복하며 노래합니다. 다른 사람이 들어와 자기 궤적을 더합니다. 방 전체가 층층이 합주를 쌓아 올립니다.

이것이 조건 10개를 모두 통과하는 이유:

1. **음악지식 0** — 움직임만 있으면 됨
2. **5초 이해** — 그리면 소리 나고, 놓으면 혼자 반복함
3. **망가지지 않음** — 그리드 + 스케일 양자화
4. **표현력** — 궤적의 모양이 곧 프레이즈. 실제로 다름
5. **다인이 진짜 재미있음** — 합주는 개인의 합이 아님
6. **Spectacle** — 빛의 궤적이 쌓이는 벽
7. **Personal에서도 재미** — 제스처 루퍼
8. **Visual identity 강함** — 잔광(afterglow) 자체가 아이덴티티
9. **반복 가능** — 매번 다른 합주
10. **Christmas 이후 생존** — 세계만 바꾸면 됨

# 7. 여섯 개의 근본적으로 다른 콘셉트

## A. AFTERGLOW — 움직임이 루프가 된다
- **One-line:** 당신의 움직임이 빛의 궤적이 되고, 그 궤적은 박자에 맞춰 영원히 노래한다.
- **은유:** 장노출 사진 / 불씨의 잔광
- **First 5s:** 손을 움직이면 빛이 따라오고 소리가 난다
- **First 30s:** 손을 내리면 궤적이 떨어져 나가 혼자 반복한다 — "어? 나 없이도 계속하네"
- **3분 루프:** 궤적을 5개까지 쌓고, 지우고, 다시 만들며 자기 곡을 편집
- **음악 생성:** 궤적 = 프레이즈. Y=음높이, 속도=밀도. 그리드+코드에 양자화
- **Safety:** 스케일/코드톤 스냅 + 1/8 그리드 + 레지스터 분리
- **Agency:** 높음 — 궤적 모양이 실제로 다른 프레이즈를 만듦
- **Solo:** 자기 루프를 쌓아 곡을 만듦
- **2인:** 두 루프가 같은 박에 떨어지면 브리지가 생기고 화성이 잠김
- **Group:** 6명 = 6성부. 집단 임계치에서 클라이맥스
- **Media Wall:** 매우 강함 — 궤적이 쌓인 벽 자체가 작품
- **Personal:** 강함 — 제스처 루퍼
- **Christmas:** 강함 — 작은 빛들이 모여 캐럴이 됨
- **일상:** 강함 — 루프 기반 음악 장난감
- **난이도:** 기술 중상 / 비주얼 중
- **최대 리스크:** 루프가 쌓이면 음향적 진흙탕이 될 수 있음 → 밀도 제한 필수

## B. GRAVITY — 사람 사이의 거리가 화성이다
- **One-line:** 가까이 서면 협화음, 멀어지면 긴장. 음악은 방의 사회적 기하학이다.
- **Agency:** 낮음 (내 행동의 결과가 모호)
- **Solo:** 성립하지 않음 — **Personal 불가**
- **강점:** 협업이 유일한 메커니즘
- **리스크:** 인과가 안 읽힘. 5초 안에 이해 실패

## C. SHADOW CHOIR — 실루엣이 목소리다
- **One-line:** 당신의 그림자가 빛으로 차오르고, 노래한다.
- **First 5s:** 최고 — 그림자는 설명이 필요 없는 가장 오래된 인터랙티브 매체
- **Agency:** 낮음 — 팔을 들면 열린다, 그게 전부
- **강점:** 즉각성, 아름다움, 성가대 = 크리스마스 네이티브
- **약점:** 30초면 전부 발견됨. 반복 가치 낮음. 선례 많음

## D. CALL & RESPONSE — 벽과의 대화
- **One-line:** 벽이 한 소절 부르면, 당신이 몸으로 답한다.
- **강점:** 턴테이킹은 즉시 이해됨. 예시로 가르침
- **약점:** **행사장에서 치명적** — 8명이 순서를 기다려야 함. 처리량 문제

## E. WEATHER — 하나의 유체를 함께 젓는다
- **One-line:** 방은 유체이고, 모두가 같은 물을 젓는다.
- **강점:** 군중 규모에 무한 확장, 역할 불필요
- **약점:** "내가 한 게 맞나?"가 해결 안 됨. 인과 확산 = 핵심 요구 위반

## F. BELL TOWER — 빛의 기둥을 친다
- **One-line:** 큰 빛기둥 사이를 지나가면 종이 울린다.
- **강점:** 5초 이해 만점. 아이들이 즉시 이해
- **약점:** 실로폰. 60초면 끝. 차별성 거의 없음

# 10. Recommended Product Direction

## Product Thesis
> **당신의 움직임은 사라지지 않는다. 빛이 되어 남고, 박자에 맞춰 스스로 노래하며, 다른 사람의 빛과 만나 합주가 된다.**

## Core Delight
"내가 손을 내렸는데 — 화면이 계속하고 있다."
행위가 사물이 되는 순간. 이것이 Soundgo에도 Handvox에도 없는 감각입니다.

## Soundgo와의 차이
Soundgo는 **연주**입니다(손을 떼면 끝). AFTERGLOW는 **작곡**입니다(손을 떼면 시작).

## Handvox와의 차이
Handvox는 사용자에게 조성을 고르라고 요구합니다. AFTERGLOW는 조성을 **세계(World)의 속성**으로 감춥니다.

## Silent Night prototype과의 차이
프로토타입은 정해진 곡을 통과시킵니다. AFTERGLOW는 곡이 **매번 새로 생성**됩니다.

## Target User
7세~성인. 음악 경험 무관. 교회 성도, 어린이, 청소년, 가족, 비기독교인 방문자.

## Long-term Moat / IP
**"제스처 → 양자화된 루프 → 집단 합주" 엔진.** 세계(World)는 교체 가능한 데이터입니다. 이것이 IP이고, 크리스마스는 그 위의 첫 콘텐츠입니다.

# 11. Core Interaction

```
손을 든다        → 살아있는 소리가 손을 따라온다        (즉각 인과, 5초)
움직인다         → 빛의 궤적이 그려진다                (시각 = 청각)
손을 내린다      → 궤적이 떨어져 나가 루프가 된다       (마법의 순간, 30초)
반복한다         → 루프가 쌓여 곡이 된다               (3분)
둘이 맞춘다      → 브리지가 생기고 화성이 잠긴다        (협업)
넷 이상 맞춘다   → 클라이맥스                          (집단)
```

**결정적 설계:** 그리는 동안 **이미 소리가 납니다.** 이것이 Silent Night 프로토타입 대비 인과가 강한 이유이며, 5초 룰을 통과하는 이유입니다. 루프화는 보상이지 인과의 시작이 아닙니다.

# 12. Musical Intelligence

## 사용자가 통제하는 것
- 궤적의 모양 (Y = 음높이 윤곽)
- 궤적의 속도 (밀도 / 리듬 분할)
- 언제 놓을 것인가 (프레이즈 길이)
- 몇 개를 쌓을 것인가
- 무엇을 지울 것인가
- 벽과의 거리 (친밀도 / 리버브)

## 시스템이 대신 처리하는 것
- 조성 / 스케일 (World의 속성)
- 코드 진행 (시간이 굴림, 8~16마디 순환)
- 그리드 양자화 (1/8, 스윙 옵션)
- 레지스터 할당 (사람마다 다른 옥타브 대역 → 충돌 방지)
- 성부 수 제한 / 밀도 제한
- 게인 밸런싱 (새 루프는 2마디에 걸쳐 페이드인)
- 오래된 루프 은퇴 (FIFO, 5개 초과 시)

## Safe but Expressive를 지키는 장치
Handvox의 철학을 차용합니다 — **부정확함을 흡수하되 의도는 보존.**

- 음높이: 스케일 스냅이지만 **코드톤 가중** (강박에는 코드톤, 약박에는 경과음 허용)
- 리듬: 1/8 그리드지만 **±30ms 이내는 그대로 둠** (인간적 그루브 보존)
- 궤적이 거의 직선이면 → 지속음 하나. 궤적이 복잡하면 → 많은 음. **모양이 실제로 결과를 바꿉니다.**

> 이 마지막 항목이 "뭘 해도 똑같잖아" 실패를 막는 핵심입니다.

# 16. Christmas World

**세계는 데이터입니다.** `SILENT NIGHT` 월드가 정의하는 것:

```
음계        : 자연단음계 → 병행장조 (밤 → 새벽)
진행        : 16마디 순환, 캐럴 화성 관용구
음색        : 종, 하프시코드 유사 플럭, 낮은 합창 패드, 숨소리
색온도      : ember → gold
클라이맥스  : 조성 반음 상승 + 종 성부 진입
```

**Christian meaning이 인터랙션에 있는 방식:**
- 혼자서는 **절대** 클라이맥스에 도달할 수 없습니다. 4명 이상의 루프가 정렬되어야 합니다.
- 각자의 작은 궤적은 그 자체로는 단편입니다. 합쳐질 때만 곡이 됩니다.
- 사람이 떠나도 궤적은 잠시 남습니다.

# 18. Visual Direction Strategy

## 세 방향 (Figma 제작 완료)

**A · EMBER** — 따뜻한 어둠. 빛이 네온이 아니라 **가열된 필라멘트**처럼 행동. 궤적은 얇고 정밀하며, **밝기가 의미를 운반**합니다(뜨거움 = 지금). 참가자는 흑체복사 색온도.

**B · VELLUM** — 의도적 반전. 따뜻한 종이 + 필사본 안료. 어두운 공간에서 **벽 자체가 조명이 되어 관객을 비춥니다.** 거리 가독성 최고. 그러나 **살아있지 않고 인쇄된 데이터처럼 보입니다.**

**C · AURORA** — 차갑고 깊은 청록. 볼류메트릭 리본. 가장 즉각적으로 인상적이지만 — 실제로 만들어 보니 **리본이 서로 녹아들어 개별 저작성이 사라집니다.** 6명이 모두 같은 청록으로 보입니다.

# 21. Motion & Interaction Specification

| Input | Intent | Music | Visual | Timing | Multiplayer effect |
| --- | --- | --- | --- | --- | --- |
| 사람 감지 | "나를 봤다" | 룸톤 +6dB, 펄스가 들리기 시작 | 발밑 웅덩이 0→100%, 승인 링 확산 후 소멸 | 안정 감지 후 120ms, 웅덩이 600ms ease-out, 링 900ms | 각자 웅덩이 추가, 필드 온기 +8% |
| 손 상승/이동 | "그린다" | **즉시 라이브 음** — Y=음높이(코드톤 스냅), 속도=필터 밝기 | 손끝에서 필라멘트 연장, 밝기=속도 | **오디오 온셋 ≤60ms** (인지 임계 아래), 시각 스무딩 40ms | 사람별 레지스터 대역 분리 |
| 손 하강 / 400ms 정지 | "놓는다" | 프레이즈가 1/8 그리드에 스냅, 다음 마디부터 루프 | 궤적이 분리되어 40px 상승, 밝은 펄스가 궤적을 1회 통과 | 다음 마디 경계(최대 2s), 분리 300ms ease-out | 신규 루프는 −12dB에서 2마디에 걸쳐 정상 게인 |
| 손 높이 (Y) | 음높이 윤곽 | 스케일 내 음높이, 강박은 코드톤 가중 | 궤적 Y 위치 | 연속, 60ms 스무딩 | 레지스터 충돌 방지 |
| 좌우 속도 | 밀도 | 리듬 분할 (느림=2분음표, 빠름=16분) | 필라멘트 굵기 + 스파크 | 120ms 스무딩 | — |
| 벽과의 거리 (Z) | 친밀도 | 리버브 센드, 가까울수록 드라이 | 기둥 밝기, 궤적 초점 | 800ms 스무딩 (떨림 방지) | — |
| 두 루프 동기 | "우리가 맞았다" | 3도/5도로 잠김 + 공유 서브베이스 | 두 웅덩이 사이 브리지 아크 | 2마디에 걸쳐 감지, 400ms 드로우 | **2인 이상 전용** |
| 루프 4개 정렬 | 집단 보상 | 조성 상승 + 종 성부, 8마디 | CLIMAX — rail에서 빛기둥, 필드 2.5× | 마디 경계 트리거, 1.4s 상승, 8마디 유지 | **정의상 solo 불가** |
| 사람 이탈 | 인계 | 루프 4마디에 걸쳐 페이드 후 은퇴 | 궤적 유령화, 하강, 바닥 안착 | 6s 유예 후 감쇠 시작 | 필드 게인 재분배 |
| 슬롯 5개 초과 | 편집 | 가장 오래된 루프 은퇴 (FIFO) | 가장 오래된 궤적 어두워지며 가라앉음 | 1.2s 크로스페이드 | — |

**Decay 원칙:** 어떤 것도 즉시 사라지지 않습니다. 모든 소멸은 최소 1.2초의 잔광을 가집니다. 제품 이름이 곧 모션 원칙입니다.

# 22. Technical Architecture

| 레이어 | 선택 | 이유 |
| --- | --- | --- |
| **추적 (Wall)** | MediaPipe **Pose** Landmarker, `numPoses: 8` | 3~5m 거리에서 **Hand Landmarker는 실패합니다.** Pose는 손목을 안정적으로 제공하고 다인을 네이티브 지원 |
| **추적 (Personal)** | MediaPipe **Hand** Landmarker | 근거리에서 해상도 높음 |
| **오디오 클럭** | Tone.js `Transport` | 공유 클럭이 제품의 심장. Soundgo가 갖지 않은 바로 그것 |
| **신스** | Web Audio + Tone.js 샘플러 | 종/플럭은 샘플이 사인파보다 압도적으로 나음 |
| **렌더** | **PixiJS v8** + 커스텀 블룸 | 3840×1080 @60fps에서 Canvas 2D는 죽습니다. Three.js는 과합니다 |
| **잔광** | **지속 프레임버퍼 피드백** | 매 프레임 지우지 않고 이전 프레임을 ~4% 감쇠시켜 누적. **이것이 AFTERGLOW를 AFTERGLOW로 만드는 렌더링 기법입니다** |
| **워커** | 추적을 Web Worker로 | 추론이 오디오 스케줄러를 막으면 안 됨 |

**채택하지 않은 것:** WebGPU(브라우저 편차), Web MIDI(불필요), 마이크(공공 공간 붕괴 — Handvox의 교훈), AudioWorklet 커스텀 DSP(1차에는 과함).

**Wall과 Personal이 같은 제품인 이유:** 추적 레이어만 다르고 그 위 전부가 동일합니다.
```
Pose(손목) 또는 Hand(검지) → {x, y, z, velocity} → 동일한 Trace 캡처 파이프라인
```
**같은 제품, 다른 악기 표면**이 성립합니다.

4. **Soundgo의 가장 가치 있는 원칙** — 0마찰 진입과 OFF 존.
5. **Handvox의 가장 가치 있는 원칙** — 히스테리시스·홀드로 **부정확함을 흡수하되 의도는 보존**.
6. **음악이론 UI 제거해도 표현력 가능한가** — 가능합니다. 이론을 **World와 시간**으로 옮기면 됩니다.
7. **미디어월에 적합한 입력** — **Pose.** Hands는 3m에서 실패, voice는 공공 공간에서 붕괴.
8. **Personal과 4~8인을 같은 제품으로 묶을 수 있는가** — 가능합니다. 추적 레이어만 교체되고 위는 동일합니다.
9. **Christmas World와 엔진 분리** — World = {스케일, 진행, 음색, 색온도, 클라이맥스 규칙} 데이터. 엔진은 World를 모릅니다.
10. **Gimmick 회피** — 축적(루프가 쌓임)과 편집(지우고 다시)을 넣습니다. 한 번 놀라고 끝나는 것에는 축적이 없습니다.
11. **핵심 IP** — 제스처 → 양자화 루프 → 집단 합주 엔진.
12. **Figma vs Creative Coding 역할** — Figma: 구성, 색·재질, 상태, 타이포, 공간 위계, 전환 의도. Coding: 실시간 움직임, 파티클, 물리, 센서 변환.
13. **Figma는 어디까지** — Figma는 **키프레임**(정지 순간의 미감)을 정의합니다. 궤적의 실제 형태는 procedural입니다. Figma가 정의하는 것은 궤적의 **재질과 밝기 규칙**이지 좌표가 아닙니다.
14. **디자인 시스템이 generative를 제한하지 않으려면** — 토큰을 **값이 아니라 규칙**으로 정의합니다. "trace/core는 #FFE8C4"가 아니라 "궤적의 머리는 항상 꼬리보다 밝고 색온도가 높다." Figma 변수는 그 규칙의 한 인스턴스입니다.
